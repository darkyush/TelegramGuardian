# Telegram Guardian 2.0

نسخه توسعه‌یافته Android/Kotlin برای ورود به حساب تلگرام و مدیریت نشست‌های فعال با TDLib.

## امکانات پیاده‌سازی‌شده در کد
- اتصال به TDLib از طریق کتابخانه native اندروید و Java API
- ورود با شماره تلفن، کد تأیید و رمز دومرحله‌ای
- ذخیره پایگاه داده TDLib در حافظه خصوصی برنامه
- رمزگذاری کلید دیتابیس TDLib با Android Keystore
- نمایش نشست‌های فعال، دستگاه، پلتفرم، نسخه، IP، موقعیت تقریبی و زمان آخرین فعالیت
- بستن نشست انتخابی
- بستن تمام نشست‌ها به‌جز نشست جاری؛ فقط در صورت تشخیص دقیق یک نشست جاری
- زمان‌بندی بررسی خودکار با WorkManager در بازه ۲۵ ساعته و تأخیر اولیه ۲۵ ساعت
- فعال/غیرفعال‌کردن محافظت خودکار از داخل برنامه

## پیش‌نیاز API
از https://my.telegram.org مقدار API ID و API Hash برنامه را بگیر.

برای توسعه محلی، فایل `secrets.properties` را در ریشه پروژه بساز (این فایل در Git نادیده گرفته می‌شود):

```properties
TELEGRAM_API_ID=123456
TELEGRAM_API_HASH=your_api_hash
```

یا متغیرهای محیطی `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را تنظیم کن.

برای GitHub Actions، همین دو مقدار را در Settings → Secrets and variables → Actions به‌عنوان Repository secrets بساز.

**API ID و API Hash را در کد، پیام‌ها، یا مخزن عمومی قرار نده.** در APK نهایی هر مقدار build-time قابل استخراج است؛ بنابراین این دو شناسه را به‌عنوان اعتبار محرمانه حساب کاربر تلقی نکن و هیچ‌وقت کد ورود، رمز دومرحله‌ای یا فایل session را به سرور/GitHub نفرست.

## اجرای محلی
1. پروژه را در Android Studio باز کن.
2. Gradle Sync را انجام بده تا وابستگی TDLib از Maven Central دریافت شود.
3. `secrets.properties` را بساز.
4. برنامه را روی دستگاه Android 8.0 یا بالاتر اجرا کن.
5. شماره، کد و در صورت نیاز رمز دومرحله‌ای را داخل خود برنامه وارد کن.

## رفتار محافظت ۲۵ ساعته
- زمان‌بندی فقط پس از فعال‌سازی صریح کاربر انجام می‌شود.
- نخستین اجرای خودکار پس از ۲۵ ساعت درخواست می‌شود؛ اجراهای بعدی نیز با فاصله دوره‌ای ۲۵ ساعت برنامه‌ریزی می‌شوند.
- این زمان‌بندی به معنی اجرای دقیق در دقیقهٔ ۲۵:۰۰ نیست. WorkManager تضمین زمان دقیق نمی‌دهد؛ Doze، محدودیت باتری، نبود شبکه یا توقف اجباری برنامه می‌تواند اجرا را عقب بیندازد.
- پس از فعال‌سازی، کار زمان‌بندی‌شده می‌تواند بدون باز بودن صفحهٔ برنامه اجرا شود؛ با این حال سیستم‌عامل ممکن است آن را به تعویق بیندازد.
- در هر اجرا فقط نشست‌هایی حذف می‌شوند که TDLib آن‌ها را `isCurrent == false` اعلام کند.
- اگر دقیقاً یک نشست جاری شناسایی نشود، حذف خودکار متوقف می‌شود (fail-closed).

## نکات مهم
- وابستگی TDLib Android از پروژه community-maintained `io.github.tdlib-android` دریافت می‌شود؛ نسخه AAR و native binary باید هنگام Gradle Sync از Maven Central قابل دریافت باشد.
- این سورس در محیط فعلی هنوز با Android SDK/Gradle کامپایل نشده است؛ بنابراین صحت نهایی APIهای کتابخانه و اجرای native تأیید نشده است.
- ورود واقعی، نمایش و خاتمه نشست‌ها باید روی یک دستگاه اندرویدی و با حساب آزمایشی مجاز تست شوند.
- هیچ APK تا پیش از موفقیت Gradle build و این آزمایش‌ها «تأییدشده» محسوب نمی‌شود.
